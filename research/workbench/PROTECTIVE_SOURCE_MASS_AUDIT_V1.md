# Controlled protective-source allocation-mass audit V1

This is a non-financial audit of the closed five-source and six-source
AdaHedge studies. The added source was technically admitted, but its own
wealth protection did not become a main-account guarantee. The controlled
six-source outcome remains rejected at J1464/301 completions/zero qualifiers.

## Frozen question and Interface

At all121 original same-clock initial/month-end origins, separate the
added source's direct allocation term from redistribution among the
retained five. Use the original before/after binary64 records, not another
learner, regenerated loss stream or hypothetical funded account.

The Module has a source-record Interface and pure signed-allocation
Implementation. The cached-record Adapter and synthetic-record Adapter
cross the same Seam. Existing saved-opinion guards, allocation-fraction
guards, scalar summaries and Fraction/prefix patterns are reused from
the previous nested/pair allocation audits. No new framework, expert
admission, source RF view or main-account engine is introduced.

For retained opinions P, old weights w5, new retained weights w6 and
added-source mass a, the exact-input linear identity is:

```text
B5 = sum(w5[i] * P[i])
A  = a * (P_added - B5)
R  = sum((w6[i] - (1-a) * w5[i]) * P[i])
A + R = B6 - B5
```

Independent Fraction arithmetic uses each original binary64 value as an
exact rational. Both stored target vectors are preserved and checked
against the corresponding linear reconstruction at the unchanged1e-12
unit/target limit. Their original NumPy reduction order is not rewritten.
Signed components need not be nonnegative and are not executable targets,
short positions, orders or capital-account profit.
