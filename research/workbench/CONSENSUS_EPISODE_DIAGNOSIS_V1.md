# Stored consensus drawdown-episode diagnosis V1

This is one fixed read-only diagnostic, not another financial rule, source
admission, account simulation or rescue of the rejected consensus policy.
It asks whether new-versus-control maximum drawdowns describe the same
retained peak/trough dates, and separates those maxima from stored NAV changes
over identical close dates.

Predeclare all four original paths and three roles: the completed consensus
policy, rolling-seven primary control and equal-seven secondary context.
Use only their immutable completed receipts and recorded account NAV.
Include the original USD10000 initial peak at the previous actual session.
Use the first exact worst trough and first exact preceding maximum;
record the first later recovery to that retained peak, if present.
No smoothing, filling, norm/window search or changed financial threshold is allowed.

For each new policy's own episode, report both controls' stored close-to-close
changes over those same dates and their drawdown from their own retained peaks
at the new trough. These ratios do not create or reset an account. They are
not replacement maximum drawdowns, fee-free counterfactuals, PNL attribution,
return forecasts or a unique causal explanation of the failed policy.

The scheme, code, tests and exact twelve receipt/account pairs are frozen
before the actual diagnostic arithmetic. Cached drawdown consistency uses
one declared1e-12numerical check; disagreement stops this identity rather
than changing the data, precision or tolerance. CAGR, Sharpe and qualification
are not recomputed. Ex-post extreme dates are not predictive filters or
independent forward evidence.

Public output contains only aggregate episode dates and percentage diagnostics,
not source prices, targets or raw daily NAV rows. Financial trial counts,
original rules, financial rejections, source refusals and forward identities
remain unchanged. No new financial policy is selected by this diagnosis.
